这是给另一个 AI 的项目包。读完这一份，再读 `sdm01-meter.yaml`，然后按下面的顺序读 `docs/`。不要根据旧段落“修正”正在运行的配置。

打包日期：2026-11-27。仓库路径原来是 `d:\esphome`。本包不含密码、API key、CA 私钥、整片备份和编译产物。

## 这是什么

实习生在一台 **Bituo SDM01-EWM** 电表上做一期：只用 **ESPHome 官方组件和 YAML**，证明 ESP8685 能同时做到下面几件事。做不到的写进评估报告，不在 YAML 里用 lambda 补。

1. ESP8685 做 Modbus 主站，读出地图第 3.2 节全部 39 个测量点。
2. 用 ESPHome 原生 API 进 Home Assistant。实体单位可用。能源面板里只有总正向、总反向。
3. 用 ESPHome 原生 MQTT，TLS 连 Broker。一个传感器一个 Topic，载荷是纯文本数字，不是 JSON。
4. 配网回退、OTA、原厂备份恢复可用。
5. 最后写《原生 ESPHome 评估报告》。这一步是工单 **T11，还没写**。

固定版本：**ESPHome 2026.10.2**。不要升级。配置键以这一版的 `esphome config` 为准。

一期明确不做，做成了结论就不算数：

- lambda、自定义 C++、external components、`custom_pdu`
- 原厂单条 JSON `/data`，以及 `/mdata`、`/cmd`、`/cdata`
- 自创 Topic，或把字段改成原厂的 X/Y/Z
- 写任何 Modbus 寄存器（清电能、LED、改地址、写序列号）
- 为了让数字像 220 V 而改成 `FP32_R` 或加 `multiply`
- 扫波特率、扫从机地址
- `web_server`、`esp32_improv`（Improv 试过，已去掉，见下）
- BTHome、按需才打开热点、量产烧录

## 硬件（以实测为准）

| 项 | 事实 |
|---|---|
| 芯片 | ESP8685，ESP32-C3 系列，QFN28 v0.4，片内 Flash 4MB |
| MAC | `<电表MAC>` |
| 设备名 | `sdm01-meter`（HA 里显示 Sdm01-Meter） |
| 现网地址 | `<电表IP>`（DHCP，会变；以当时 ping / 日志为准） |
| Wi-Fi | 只用 2.4 GHz。现场网是 <2.4GHz网络>，信道 11。电脑在 5 GHz 时先改过来再编译、OTA、看日志 |
| 下载口 | 7 针，115200。板子 TX = GPIO21，板子 RX = GPIO20。接 USB-TTL 时交叉，共地，**3.3V**。IO9 对 GND 短接后上电才进下载模式。黄色短接帽就是这一处，只有一个 |
| 计量口 | 板内 UART1：TX = **GPIO0**，RX = **GPIO1**，19200、8N1，从机地址 **247**。已经接到计量 MCU，不要接到 USB-TTL |
| 绿色 RS485 | 外壳底部，9600、8N1、地址 247。只给电脑直读对照。这组参数**不要**写进 `uart:` |
| 供电纪律 | 单独操作不接市电，ESP 靠 USB-TTL 的 3.3V。带电必须导师在场（漏保 + 隔离变压器 + 光隔离 TTL）。只刷 ESP，不动计量 MCU。刷 ESP 不影响计量，导师 2026-10-30 已确认 |
| 日志 | `logger.baud_rate: 0`。日志走 `esphome logs`（API），不走下载串口。确认 Wi-Fi 上线后拔掉 TTL。没有市电时拔掉 TTL 设备会断电。只靠 TTL 的 3.3V 不要 OTA |

GPIO21/GPIO20 是下载口，不是计量口。2026-11-19 上午用 21/20 读电压全部超时；下午按电路图改成 GPIO0/GPIO1 后，A 相电压和绿色 RS485 一致（约 220 V）。`docs/实施规格.md` 第 3 节和 B2 仍写着 21/20，那是旧任务书。**计量口以 `sdm01-meter.yaml` 和 `docs/确认表.md` 的 B11 为准。**

超过约 5 秒没有一次合法 Modbus 请求，计量侧把 SoC 看成离线，绿灯约 4 秒闪一次。现在的轮询是 10 秒。私有示例仓库把间隔做成 2 秒，一期没有改。上电后几秒内的异常 `0x06` 是计量侧还在忙。板上没有空闲 GPIO。出厂没开 Secure Boot 和 Flash Encryption，不要去开。

## 现在芯片上跑的是什么

仓库里的 `sdm01-meter.yaml` 和芯片上的固件一致。

- 注释：`T6.3 emqx public 8883`
- 编译时间：`2026-11-26 13:17:53 +0800`
- 框架：ESP-IDF，`variant: esp32c3`，板型 `esp32-c3-devkitm-1`
- 打开了 `CONFIG_MBEDTLS_HAVE_TIME_DATE`，错误时间才会让 TLS 失败
- `api` 加密、`ota` 密码、Wi-Fi、云端 Broker 和 CA 都是 `!secret`
- MQTT：`broker.emqx.io` 的公钥，端口 8883，**没有用户名密码**，**没有 `topic_prefix`**，`discovery: false`
- SNTP：`ntp.aliyun.com`
- `modbus_controller` 地址 247，`update_interval: 10s`，功能码 03（`holding`），`value_type: FP32`
- 39 个测量传感器，地址 1000 到 1076，步长 2
- 另有一个 `debug` 传感器 `Heap Free`，10 秒一次
- 热点名 `SDM01-Setup`，无密码，配合 `captive_portal`。连不上 Wi-Fi 才出现。按需热点只记录，没实现
- 没有 `web_server`，没有 `esp32_improv`，没有 lambda，没有写寄存器

主题形式是 `sdm01-meter/sensor/<名字>/state`，载荷是纯文本数字。`sdm01-meter/status` 在线时是 `online`。公共 EMQX 上这些主题任何人都能订到。

Home Assistant 在 `<HA的IP>:8123`。这一台的集成条目是 `<集成条目>`。实体平台是 `esphome`，不是 MQTT。不要开 `discovery: true`，否则会多出第二套实体。现场还有另一台 `<另一台电表>`，操作时用这条集成 ID，不要按名字点错。

能源面板只加了：

- `sensor.sdm01_meter_total_import_energy`
- `sensor.sdm01_meter_total_export_energy`

进出合计和分相没有加。旧来源 `sensor.<另一台设备IP>_total_forward_energy` / `total_reverse_energy` 留在配置里，实体未定义，不要删。

电能规则（导师 2026-11-19）：

- 正向、反向只会增加，不会被清零。`state_class: total_increasing`。地址 1054、1056、1060、1062、1066、1068、1072、1074。
- 进出合计是绝对值相加。不写 `state_class`，不进能源面板。地址 1058、1064、1070、1076。
- 功率单位是 kW / kVAR / kVA。电流不平衡度没有 `device_class`，单位 `%`。不加 `multiply`，不设小数位。

最近一次记下的读数（2026-11-27 11:46，记录被要求停下）：集成 loaded，A 相电压 220.81 V，总进口 333.08 kWh，总出口 0，空闲堆 152748 字节。通过门槛没有判。

## 接着做时不要动的东西

除非用户明确要求改某一项：

- 不要升级 ESPHome。
- 不要把计量口改回 GPIO21/GPIO20，不要把绿色口的 9600 写进 `uart`。
- 不要扫波特率和从机地址。读不通就停，把现象记下来。
- 不要加 lambda，不要写 Modbus 寄存器，不要清电能。
- 不要把 `discovery` 改成 true，不要自编 `topic_prefix`。
- 不要把 `logger.baud_rate` 改成非 0。
- 不要把 1 秒轮询留在长期配置里。
- 不要为了 TC10 再刷一版去“修”OTA 密码。
- 不要自己通市电。
- 电能 `state_class` 和能源面板来源保持现在这样。
- 评估报告里的差距项不要写成“已经用 lambda 补上”。
