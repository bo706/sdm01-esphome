## 1. 一期要证明的事

只用官方原生组件和 YAML，这台电表要同时做到：

1. ESP8685 作为 Modbus 主站，读出地图第 3.2 节的全部测量点。
2. 用 ESPHome 原生 API 接入 Home Assistant，实体单位和能源面板可用。
3. 用 ESPHome 原生 MQTT 接入云端 Broker（TLS，自有 CA）。一个传感器一个 Topic，内容是纯文本。
4. 配网回退、OTA、备份恢复可用。
5. 写出《原生 ESPHome 评估报告》，把原生做不到的地方留给二期。

## 2. 一期不做

这些做成了，一期结论就不算数。发现需求时记入评估报告的差距项，不在 YAML 里补。

- 自定义 C++、external components、lambda、`custom_pdu`
- 原厂单条 JSON `/data`，以及 `/mdata`、`/cmd`、`/cdata`
- 自创 Topic 格式或字段名（含把原生 Topic 改成 X/Y/Z）
- 写任何 Modbus 寄存器（序列号、波特率、从机地址、清电能、LED、广播改地址）
- BTHome、按需触发配网、量产烧录
- 为了让数字“看起来像电压”而改字序、改缩放

## 3. 架构（Grill 已对齐）

```
市电 / CT → 计量 MCU（采样、校准、电能累计、对外 RS485）
                │  板内串口 Modbus RTU
                ▼
           ESP8685（只刷这一颗）
            │                │
     ESPHome 原生 API      原生 MQTT（TLS）
            ▼                ▼
      Home Assistant      云端 Broker
```

- 只刷 ESP8685。计量 MCU 不动。累计电能在 MCU 里，ESP 重启不得把它清零；清零只会发生在写入清电能寄存器时，一期禁止写。
- ESP 是主站，先发问。MCU 是从站，只回答。
- ESP 读数走 GPIO21（TX）/ GPIO20（RX），19200、8N1。不走外壳底部绿色 RS485 端子。
- 绿色 RS485 是 MCU 对外的口，默认 9600、8N1、从机地址 247。只给电脑直读对照，参数不能抄进 ESP 的 `uart:`。
- HA 和 MQTT 是两条连接。关掉一边，另一边继续。
- 原厂固件在覆盖前整片备份两次，两份文件必须一致。恢复时把备份整片写回。

## 5. 规格决定与假设

审核时请直接改决定。假设在第一次读数核对之前，不能复制到全部传感器。

**【规格决定】**

- 功能开发阶段 `update_interval: 10s`。任务书骨架示例是 5s；过密轮询是已知风险。稳定性测试再按 1s、5s、10s 各跑一轮，不把 1s 放进日常配置。
- 测量寄存器使用 `register_type: holding`（功能码 03）。地图写 03 和 04 都支持。若帧超时，只把这一项改为 `read`（功能码 04，ESPHome 里是 `input` 的别名）再试一次。仍失败则停，不同时改波特率或地址。
- 实体名用地图的 A/B/C，例如 `Voltage A`。原厂 MQTT 的 X/Y/Z 不在一期对齐，写入差距项。
- 基线配置包含：`api`、`ota`、`wifi` + `ap`、`captive_portal`、`time`（SNTP）、`mqtt`、`uart`、`modbus`、`modbus_controller`、测量 `sensor`、诊断（`wifi_signal`、`uptime`、`debug`、重启按钮）。
- 基线不包含 `web_server` 和 `esp32_improv`。稳定性或配网测试要加时，先看空闲堆。堆不够就去掉，并写入评估报告。
- SNTP 服务器草稿用 `ntp.aliyun.com`，随网络环境改。
- 开发阶段日志级别用 `DEBUG`，第一条电压核对通过后改为 `INFO`。`baud_rate: 0` 始终保持。
- ESPHome 固定为 **2026.10.2**（2026-11-12 `esphome version`）。之后不随手升级。配置键以该版本的 `esphome config` 为准。最小配置 `sdm01-meter.yaml` 已通过 `esphome config`，2026-11-12 已编译并刷入。设备在 2.4GHz（信道 11）上线，并完成一次只改 `comment` 的 OTA。

**【假设】**

- 地图的 FLOAT32、大端 ABCD，对应 ESPHome `value_type: FP32`（两个寄存器，高字在前）。`FP32_R` 是低字在前，不对就不要换。
- 第一条传感器必须是 A 相电压，地址 1000。数值要和同一时刻的 RS485 直读一致（符号、单位、数量级）。不一致时停下来，对照原始字节，问导师。禁止换字序直到数字落在 200～250。
- 无市电时，T3 只读一条识别字符串做通信冒烟（优先固件版本，地址 135）。不读序列号。识别字符串不计入 F2。组件名实施时对照该 ESPHome 版本的官方页；没有官方 `text_sensor` 就不做，不写 lambda。

## 6. 配置边界

### 6.1 必须有的行为

| 块 | 要求 |
|---|---|
| `logger` | `baud_rate: 0` |
| `api` | 加密 key，来自 `!secret` |
| `ota` | 平台 `esphome`，密码来自 `!secret` |
| `wifi` | STA 凭据来自 `!secret`；保留 `ap`，配合 `captive_portal`。连不上 Wi-Fi 时才回退热点 |
| `time` | SNTP。TLS 之前要有正确时间 |
| `mqtt` | 端口 8883，`certificate_authority`，`discovery: false`。`topic_prefix` 只填负责人给的值 |
| `uart` | 见 B2 |
| `modbus` + `modbus_controller` | ESP 为主站，从机地址见 B3 |
| 测量 `sensor` | 第 7 节每一行一个传感器 |
| 诊断 | Wi-Fi 信号、uptime、堆、重启按钮，HA 里可见 |

### 6.2 禁止出现的配置

- `lambda`、`custom_pdu`、任何 Modbus `number` / `switch` / `output` / 写寄存器
- MQTT 的自定义发布、JSON 拼接、`discovery: true`
- 把日志波特率设回 115200 或任何非 0 值
- 在 YAML 或 Git 里写 Wi-Fi 密码、MQTT 账号、API key、OTA 密码、私钥、公司 Broker 地址

`secrets.yaml` 只留在本机，并写入 `.gitignore`。仓库里只提交填了假值的 `secrets.yaml.example`。这些值也不贴进 AI 对话。CA 的公钥按公司规定处理，私钥不出现。

### 6.3 刷机与供电

- 实习生单独操作时不接市电。ESP 由 USB-TTL 的 3.3V 经 7 针口供电。禁止使用 5V 档。
- 进下载模式：断开市电，接 GND、GPIO20、GPIO21、3V3，IO9 接 GND 后上电。刷完断开 IO9 再上电。
- 刷完拔掉 USB-TTL。之后升级走 OTA。
- 带电对照必须导师在场，试验台有漏保和隔离变压器，USB-TTL 用光隔离型。

**【待确认】电能**

地图第 3.2 节这 12 个电能点都是 FLOAT32、单位 kWh、量程 ±1,999,999,999。表里原先把 1058、1064、1070、1076 只写在说明里，没有单独成行；2026-10-30 核对网页后已补进表。

功率单位是 kW / kVAR / kVA，不是 W / var / VA。小数位在和 RS485 对照后填写，不提前用小数位掩盖不一致。

识别字符串（地图 3.1，只读）不计入上面的测量验收：表类型 100、制造商 110、产品 ID 120、序列号 125、硬件版本 130、固件版本 135。序列号寄存器可写，一期只读，YAML 里不提供写入口。

通信参数寄存器 6000–6002、命令寄存器 10000/10001、广播改地址 30000 都是写路径。一期不配置。

## 8. Home Assistant

- 接入方式只有原生 API。HA 里每种测量只出现一次。
- 能源面板只添加导师确认过 `device_class: energy` 且 `state_class: total_increasing` 的电能实体，单位 kWh。
- MQTT 保持 `discovery: false`。若 HA 里出现第二套同名实体，先查是不是发现被打开，而不是再加一份 sensor。

## 9. MQTT 与 TLS

原生行为，不改：

- Topic 形如 `<topic_prefix>/sensor/<传感器名>/state`
- 载荷是纯文本数值
- 在线状态用 ESPHome 自带的 birth / last will

云端参数到齐之前，用本地 Broker 按这个顺序做：明文 → 本地自建 CA 的 8883 → 负责人给的云端。错误 CA、过期证书、错误时间、域名与 `broker` 不一致，四种情况都必须连接失败，设备不崩溃，HA 的 API 仍在。

证书校验依赖 SNTP 对时，以及 CA 公钥。证书上的 CN/SAN 必须和 `broker` 主机名一致。

## 11. 六个问题的处理

六项都已定案。第 4 项于 2026-11-19 按导师回复写入，同日已写入 YAML 并 OTA。

| # | 事项 | 谁定 | 结论 |
|---|---|---|---|
| 1 | 轮询间隔 | 规格定案 | 开发阶段 10s。5s 只出现在稳定性测试里 |
| 2 | 功能码 | 规格定案 | 先用 03（`holding`）。失败只改一次为 04 |
| 3 | 实体名 | 规格定案 | A/B/C。X/Y/Z 记入差距项 |
| 4 | 电能 `state_class` | 导师，2026-11-19 | 正向、反向：`total_increasing`。进出合计留空，不进能源面板 |
| 5 | 不平衡度 `device_class` | 规格定案 | 留空。官方设备类型里没有“百分数 / 不平衡度” |
| 6 | 识别字符串 | 规格定案 | 无市电的 T3 只读固件版本（地址 135） |

三问和回复：

1. 正向电能（1054、1060、1066、1072）会不会变负，或者被清零？回复：只会增加，不会被清零。
2. 反向电能（1056、1062、1068、1074）是不是单独一路、只会增加？回复：是，只会增加，不会被清零。
3. 1058、1064、1070、1076 是相加还是相减，会不会为负？回复：绝对值相加。Home Assistant 能源面板没有这一项，只有正向和反向两格，这 4 路不用放进面板。
